# Settle Window after a prompt match

Some consoles (the RTOS shell) echo the command, print their prompt at once, and only then emit the command's result asynchronously, so ADR 0003's "prompt match ends the Exec" returned the Echo and nothing else; Agents fell back to idle completion and paid for every unrelated line, or re-read the console with `serial_tail`. `serial_exec` now takes `prompt_settle_ms` (0–999, default 0): after the prompt matches, capture continues until the device has been quiet for that long, then the Exec ends by `prompt`. Zero keeps the old match-ends-now behavior; values at or above the 1 s idle gap are rejected because they would be idle completion in disguise. The Hub also removes the matched prompt text and the command Echo from `output` (the Session Log keeps both). Rejected: a per-Target default completion policy (the Agent knows which console it is talking to; the Hub should not guess), a fixed post-prompt delay (splits streamed results mid-line), and documenting "do not use prompt on rtos" instead of fixing completion. Amends ADR 0003.
