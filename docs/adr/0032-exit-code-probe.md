# Exit Code Probe replaces the Agent-side checked wrap

Agents needed the remote exit status on shell Targets and were told to assemble a `set +e; <cmd>; ec=$?; printf ...; printf "SBX_" "<hex>"` line themselves, pass the assembled token as `prompt`, and parse the trailer out of `output`. That cost Agent output tokens on every call, thirty lines of README, and a class of mistakes (unsplit token matching the Echo, `grep` dropping the trailer). `serial_exec` now takes `exit_code: true`: the Hub generates a one-time `SBX_<hex>` token, wraps the command as `<cmd>; printf '%s\n' "$?"; printf '%s%s\n' "SBX_" "<hex>"`, uses the token as its internal prompt, extracts the status line, removes both trailer lines before Grep, and reports `exit_code` (integer, or `null` when the trailer never arrived and the Exec ended by idle). The Session Log records the wrapped line the device actually received. `exit_code` is mutually exclusive with `prompt`, is not restricted by Target Name (a non-shell Target simply yields `null`), and composes with `grep` and `max_lines`. Rejected: keeping the Agent-side recipe with better docs, failing the Exec (`ok: false`) when the trailer is missing (the captured output is still useful and the Agent should not retry), a `set +e` prefix (interactive shells do not run with `-e`), and a separate `serial_exec_checked` tool.
