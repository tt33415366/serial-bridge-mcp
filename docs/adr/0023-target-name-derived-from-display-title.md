# Target Name derived from Display Title; Bindings edited in CRT Mode only

The Web UI drops the Target Name field and derives the Agent-facing Target Name from the Display Title on save (trim, lowercase, runs of anything outside `[a-z0-9_]` to `_`, cut to 32, trim `_`). Save is blocked with an inline note under the slot when the result fails `^[a-z][a-z0-9_]{0,31}$` (for example a Title with no a–z letter) or collides with the other Slot; each Slot shows its effective Target Name in that note so Agents can still be addressed by name. Because editing a Title is now also a rename, the whole Bindings panel — Display Title included — is editable only in CRT Mode, superseding “Display Title editable anytime” in ADR 0020. Derivation lives in the browser only: `POST /api/bindings`, `config.py`, and the persisted `slots[]` still take an explicit `name`, so a hand-edited or older config may hold a Title/Name pair this rule would not produce; the UI keeps showing the stored name until the Operator edits that Title. Rejected: deriving in `config.py` (couples the Agent-facing contract to an Operator label), auto-fixing an invalid slug to `slot0`/`slot1` (silently names a Target the Operator cannot see), and accepting the derived rename while Bridge Mode holds the ports.
