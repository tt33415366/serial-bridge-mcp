# Access Token: first-boot secrets file, env override, and Rotate

On first Hub boot, if no usable Access Token is loaded yet, generate `secrets.token_urlsafe(32)` and persist it to a secrets file beside the config (default `serial_bridge.token`, overridable via `SERIAL_BRIDGE_TOKEN_FILE`); never store the token in the Port Binding JSON. `SERIAL_BRIDGE_TOKEN` in the environment overrides the file for that process lifetime. If the env var is already set on first boot, mirror its value into the secrets file so removing the env later still boots. Operators may Rotate from the Setup Page (loopback only): rewrite the secrets file immediately; if env is set, warn that the running process still honors env until it is unset or the Hub is restarted without it. Rejected: token only in env with no persistence, token inside `serial_bridge.json`, and Rotate that mutates the Windows user environment.
