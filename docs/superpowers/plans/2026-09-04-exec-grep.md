# Exec Grep Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let an Agent pass an optional Grep on `serial_exec` so the returned `output` is matching lines (and optional neighboring lines) from this Exec’s full capture, applied after ANSI strip and before the 32 KiB trailing cap.

**Architecture:** Grep is a return-time filter inside `ExecEngine`, not a new MCP tool and not session-log search. Validation runs before any TX (same moment as invalid `prompt` regex). All Exec completion paths (idle, prompt, timeout, abort-with-capture) build the Agent-visible `output` through one helper so Grep cannot be applied on only some paths. Agent Trace and the Operator UI are unchanged.

**Tech Stack:** Python 3.10+, existing `serial_bridge` package, `unittest` / `python -m pytest` under `tests/`.

**Tickets:** `.scratch/exec-grep/issues/01`–`04`

**Worktree:** `D:\SourceCode\serial_bridge\.worktrees\feature-exec-grep` on branch `feature/exec-grep`

## Global Constraints

- Domain words: **Grep**, **Exec**, **output**, **Agent**, **Target**, **Hub**. Do not call Grep “filter”, “search”, “tail”, or “keyword” in code comments, docs, or glossary.
- Grep applies only to this Exec’s captured device text. Do not read session logs. Do not add `serial_grep` or persist captures.
- Order: `strip_ansi` → Grep (if requested) → 32 KiB trailing cap (`ExecEngine.OUTPUT_CAP_BYTES`). `prompt` still matches the full stripped capture before Grep/cap.
- `truncated` still means only: the returned `output` string was clipped to the last 32 KiB. Do not reuse it for “Grep ran” or “hits were dropped”.
- When Grep ran: include `grepped: true` and `match_count` (hit rows before cap, not context-only rows). When Grep did not run: omit both keys (same shape as today). Parameter errors omit both keys.
- Empty `grep=""`, invalid regex, `grep_context > 0` without `grep`, and negative `grep_context` reject before TX (`ok: false`, `error` set, no serial write). Align invalid-regex wording with prompt: `"grep is not a valid regex: {exc}"`.
- Zero hits: `ok: true` (unless timed_out/aborted), `output: ""`, `match_count: 0`, `grepped: true`.
- Case-sensitive. Pattern is applied per line (`str.splitlines(keepends=True)`). Literal: `pattern in line`. Regex: `re.search` on the line. A trailing fragment without a newline is still a line.
- Overlapping/adjacent context windows merge; each line at most once, original order. Do not inject `--` or blank separators.
- `timed_out` / `aborted` still run Grep on whatever was captured.
- Do not change Agent Trace fields or Operator UI.
- Do not change behavior when `grep` is omitted (including ignoring `grep_is_regex`).
- TDD for behavior changes: failing test first, then minimal code. Focused tests while iterating; full `python -m pytest -q` before each commit.
- Work only in this worktree/branch. Do not commit secrets (`serial_bridge.token`, `.env`).

```python
@classmethod
def _present_output(cls, text: str) -> tuple[str, bool]:
    return cls._cap_output(text)

def _result_from_capture(
    self,
    request: ExecRequest,
    captured: bytearray,
    *,
    ok: bool,
    timed_out: bool = False,
    aborted: bool = False,
    error: str | None = None,
) -> dict[str, Any]:
    output, truncated = self._present_output(self._strip_output(captured))
    return exec_result(
        request.target,
        ok=ok,
        output=output,
        truncated=truncated,
        timed_out=timed_out,
        aborted=aborted,
        error=error,
    )
```
